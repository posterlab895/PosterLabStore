## 2. Logic Chain

1. **Duplicate Back Bar Root Cause**:
   - `product.html` defines the primary back navigation button at lines 78–85. Test `F13-2` asserts that `product.html` contains this link (`index.html`), and `B13-5` asserts that `product.html` contains *exactly 1* `.page-back-bar`.
   - `script.js` in `renderDetail()` also creates `<div class="page-back-bar">` whenever `renderDetail()` generates `#productDetail.innerHTML`.
   - In `index.html`, products navigate via `<a href="product.html?id=...">`, so product details are primarily viewed on `product.html`.
   - Therefore, having `renderDetail()` inject a second `.page-back-bar` creates a duplicate navigation bar that causes visual clutter and breaks DOM simplification principles.
   - Removing `<div class="page-back-bar">` from `renderDetail()` inside `script.js` leaves the static `.page-back-bar` on `product.html` as the single authoritative navigation element. Adding `backToStore` to `translations` in `script.js` allows dynamic Arabic/English updates via `data-t="backToStore"`.

2. **Frame Styling & Test Assertions**:
   - Tests `F10-4` and `B10-4` require `.frame-white` and `.dot.white` to be defined in `styles.css`, with `.dot.white` having an explicit border (e.g. `border: 1px solid #d1d5db;`) to contrast against light buttons.
   - Test `F11-4` requires `.frame-transparent` in `styles.css`. Currently `styles.css:866` only defines `.detail-main-image.frame-none img`, but `script.js` uses `Transparent` (class: `frame-transparent`).
   - Defining `.frame-black`, `.frame-white`, `.frame-transparent`, `.frame-none`, and swatch `.dot` (`.dot.black`, `.dot.white`, `.dot.transparent`, `.dot.none`) satisfies all 3 failing tests.

3. **Smooth Dynamic Frame Switching**:
   - Currently, clicking a frame button invokes `state.detailFrame = frameButton.dataset.frame; renderDetail(state.selectedProduct);`.
   - Rebuilding `#productDetail.innerHTML` causes a full DOM destroy/recreate, preventing the CSS transition on `img` (`transition: border 250ms ease, box-shadow 250ms ease;`) from running smoothly.
   - Instead, the frame click handler can dynamically update the class on `.detail-main-image` (`classList.remove("frame-black", "frame-white", "frame-transparent", "frame-none"); classList.add("frame-" + frame.toLowerCase());`), update the `.is-selected` button states, and update the subtitle in `.price-line`.
   - This provides instantaneous, flicker-free visual transitions without full DOM reconstruction, fulfilling Feature 11 in `PROJECT.md`.

4. **White Wall-Like Gallery Background**:
   - `AuthoritativePricing.wallBackgroundGradient` in `tests/harness.js` specifies `linear-gradient(180deg, #fbfbfb 0%, #f1f2f5 100%)`.
   - Test `B12-1` requires a solid fallback color (`background-color: #f8f9fa;`).
   - Setting `.detail-main-image` with:
     ```css
     background-color: #f8f9fa;
     background: linear-gradient(180deg, #fbfbfb 0%, #f1f2f5 100%);
     box-shadow: inset 0 2px 10px rgba(0, 0, 0, 0.08), 0 10px 30px rgba(0, 0, 0, 0.04);
     ```
     and providing dark theme override `[data-theme="dark"] .detail-main-image` satisfies `F12-1` through `F12-5` and `B12-1` through `B12-5`.

5. **Non-Regression Assurance (M1 & M2)**:
   - In `script.js`, `frameOptions.Black.price = 0`, `frameOptions.White.price = 0`, and `frameOptions.Transparent.price = 0`.
   - Retaining zero price adders preserves the authoritative pricing tiers (20x30 = 180, 30x40 = 200, 40x50 = 250, 50x70 = 300) and cart math.
   - Preserving `state.detailFrame` across size selection and admin live updates ensures cross-tab and live sync updates (M2) do not unexpectedly reset the customer's frame choice.
